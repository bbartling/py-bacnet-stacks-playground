## Goal

Follow actual source paths from validated config to resource ownership and shutdown.

## Before you start

Read-only repository study first; software lab and optional isolated Pi/RS-485 bench. Follow the destination repository contract before edits. Follow [workspace and evidence conventions](LAB_GUIDE.md). Save today's work as `student-work/day107/` or in your own learning repository. Record the toolchain; commands and dependency behavior may differ across OS releases. Complete the baseline before the stretch.

## Concept

Application policy belongs at clear boundaries. router-core holds stable contracts; the adapter translates pinned upstream public APIs; routerd manages process/runtime and management surfaces. The exact source may evolve, so verify symbol names and call sites at your checkout. Local delivery and forwarded traffic are separate paths; a local-delivery counter does not prove packets crossed two interfaces.

## Tiny example

Start with adapter `validate.rs`, `ports.rs`, `route_session.rs`, and `local_delivery.rs`. Use `rg` to find construction/start/stop call sites and record file plus symbol names rather than guessing from filenames.

Use this to explore the mechanism. It is deliberately smaller than the assignment.

## Coding challenge

- Produce an annotated call graph for configuration validation, serial/socket open, router start, local delivery, metrics and stop.
- Identify which object owns each socket, tty, task and channel; note bounded/unbounded state.
- Write one small Rust test or standalone harness exploring a non-I/O validation invariant, without changing router behavior yet.

## Experiment

Follow an invalid configuration through the code. Identify whether any resource could open before validation completes, and substantiate the answer with source.

Write your prediction before running the experiment, then record what changed and why. Use the [capture guide](lab-scripts/wireshark_filters.md) when packets are involved; for offline work, preserve input bytes and actual output instead.

## Acceptance checks

- Every graph edge corresponds to an actual call or ownership relationship.
- No counter is used as evidence for a different packet path.
- The test exercises a real boundary, not merely duplicates a constant.

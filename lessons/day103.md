## Concept

MS/TP masters coordinate access using token and discovery/polling procedures. Max_Master affects the address search space; Max_Info_Frames constrains work while holding the token. Reply timing and state transitions have defined rules. USB/OS scheduling can interact with deadlines, but an arbitrary sleep-based patch is not a substitute for understanding the protocol and adapter. Avoid claiming Clause 9 conformance from a toy model.

## Tiny example

Create an event table with timestamp, source, destination, frame type and interpretation. Keep token movement separate from a confirmed BACnet application transaction riding inside data frames.

Use this to explore the mechanism. It is deliberately smaller than the assignment.

## Coding challenge

- Write a Rust offline token-timeline analyzer for a supplied or recorded multi-station trace.
- Simulate a tiny declared subset of token ownership and finite poll events with a fake clock; list excluded recovery states.
- Validate station MAC/Max_Master/Max_Info_Frames against the destination repo policy before any hardware configuration proposal.

## Experiment

Remove one expected token event from the offline trace. Explain what is observed, what is inferred and what extra capture would confirm the diagnosis.

Write your prediction before running the experiment, then record what changed and why. Use the [capture guide](lab-scripts/wireshark_filters.md) when packets are involved; for offline work, preserve input bytes and actual output instead.

## Acceptance checks

- The trace identifies actual token holders over time.
- Timing units and timestamp source are explicit.
- The simplified model is not used to certify a hardware baud or full protocol behavior.

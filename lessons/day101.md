## Concept

RTU framing relies on serial timing rules as well as byte contents. A host timestamp often marks a read completion after buffering, not the arrival time of an individual wire byte. Baud changes affect character time; the serial guide also defines timing guidance at higher rates. Measure and report what the available instrumentation can establish. A PTY cannot certify silent intervals on RS-485.

## Tiny example

For 8N1, one character occupies a start bit, eight data bits and a stop bit before considering additional gaps. Use the actual framing when calculating character time; do not apply this count to a different parity/stop-bit configuration.

Use this to explore the mechanism. It is deliberately smaller than the assignment.

## Coding challenge

- Run a read-only Rust RTU request against one independent disposable peer after passive/wiring checks pass.
- Record adapter, baud, framing, topology and CRC/outcome statistics over a finite set of requests.
- Separate host-read timestamps from any wire-level timing observations; use fixture-only analysis if no independent peer is available.

## Experiment

Compare two host read-buffer sizes while holding the wire configuration fixed. Explain why different chunk boundaries do not necessarily mean different serial frames.

Write your prediction before running the experiment, then record what changed and why. Use the [capture guide](lab-scripts/wireshark_filters.md) when packets are involved; for offline work, preserve input bytes and actual output instead.

# Day 100 — Serial ownership and orderly stop

**Week 15 · 45–90 minutes.** Prerequisites: Days 1–99, or equivalent skills. Reuse your earlier work rather than start every tool again.

## Goal

Open a serial stream deliberately and prove it can stop and reopen without fighting another owner.

## Before you start

Dedicated Pi lab or the explicitly labeled VM/offline alternative. Hardware results must come from the actual hardware. Follow [workspace and evidence conventions](LAB_GUIDE.md). Save today's work as `student-work/day100/` or in your own learning repository. Record the toolchain; commands and dependency behavior may differ across OS releases. Complete the baseline before the stretch.

## Concept

A tty is a resource with configuration and ownership. Stable `/dev/serial/by-id/` paths are preferable to assuming ttyUSB0 stays the same adapter. Host reads may split or combine protocol frames. One process should own a bus adapter; do not kill an unknown owner or open a second “observer” that changes settings. Serial shutdown must release tasks, buffers and the device handle.

## Tiny example

Inspect `/dev/serial/by-id/` and the owning process using OS tools. For the first software experiment use a pseudo-terminal pair; it proves stream/lifecycle behavior, not electrical RS-485 timing.

Use this to explore the mechanism. It is deliberately smaller than the assignment.

## Coding challenge

- Build a bounded Rust serial-stream experiment using a maintained serial API and an explicit path/config. Default to receive-only.
- Handle partial reads, idle timeout, device disappearance and a stop signal.
- Demonstrate stop/reopen on a pseudo-terminal or isolated adapter with known ownership; record which environment was used.

## Experiment

Remove only your disposable adapter or close the PTY peer during a read. Observe the actual error and verify that your process exits within its deadline.

Write your prediction before running the experiment, then record what changed and why. Use the [capture guide](lab-scripts/wireshark_filters.md) when packets are involved; for offline work, preserve input bytes and actual output instead.

## Acceptance checks

- The configured stable path and owner are recorded.
- An unknown existing owner is not terminated automatically.
- No background task retains the device after claimed shutdown.

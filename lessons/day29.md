## Concept

The application supplies bytes to a socket. UDP adds a transport header, IP handles addressing between networks, and a link layer carries the packet over one local medium. The OSI model helps ask which responsibility failed, but real protocols do not fit seven independent software boxes. A loopback capture can have a different link header from Ethernet. Capturing on `any` can produce Linux cooked records.

## Tiny example

```text
Application bytes
  inside UDP datagram
    inside IPv4 or IPv6 packet
      inside the capture interface's link-layer record
```
Use `ip -br address`, `ip route`, and `ss -lun` to inspect local state without changing it.

Use this to explore the mechanism. It is deliberately smaller than the assignment.

## Experiment

Compare a loopback capture with a capture on an actual NIC if available. Do not assume their first 14 bytes have the same meaning. Display filter: `udp or tcp or icmp or icmpv6`.

Write your prediction before running the experiment, then record what changed and why. Use the [capture guide](lab-scripts/wireshark_filters.md) when packets are involved; for offline work, preserve input bytes and actual output instead.

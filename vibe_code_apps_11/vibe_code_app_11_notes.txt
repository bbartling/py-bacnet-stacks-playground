## Phase 1 — notepad then build (human ↔ agent)

- **Today (v1 contract):** The “notepad” is **`bas_build_spec/memory/commissioning/PHASE_NOTEPAD.md`** — open **§ Step 1 “Paste your info into me”** for BACnet bind, LAN topology, building, devices, **URLs + ports**; keep **§ E phase strip** updated. Save in editor/git. On the **next wake**, Codex reads it first; if tables are still `(fill)`, it should **ask you** (or build the prompt UI) before assuming site layout.
- **Optional “baby” slice:** If you want a **web UI** with a big text area and a **Save** button that appends to that file (or an API), say so in **`PHASE_NOTEPAD`** or **`BUILD_CHECKPOINTS` / `next_directions.md`** and the **first** wake can build only that; the **following** wakes chew through BACnet/networking/read-only dashboard. The agent does **not** automatically assume a Save-button UI exists until a checkpoint asks for it.
- **“Go nuts”:** Raise work per wake with **`MINI_INVOCATIONS_PER_WAKE`** in `.env` or on the **`bas_wake.sh`** command line; still bounded by **`GUARDRAILS`** and mini budget—use bigger numbers only when you want more Codex passes in one hour.

## Vision — Day 0 unified commissioning shell (UX)

- **One URL for months:** same dial-in shell as the job ages; **phase** changes what is writable and which **tab** is primary (rough-in → Cx → TAB → BAS).
- **Layout:** **Notepad/chat + Save** | **Always-on strip** (phase, done, next, URLs+ports, BACnet health) | **Read-only telemetry** once context is saved | **Roadmap checkboxes** (commissioning acceptance rows) + **links** to run **`bas_validate_cron_services.sh`**, **`bas_validate_wake_pass.sh`**, **`bas_validate_automation.sh`** and **wake logs** (see §3–4 below) | **Electrician** (device red/green, points + sensor values) | **Technician** (read/write release) | **TAB** (K-factor, sequencing, **all valves open** hydronic demo, setpoints, charts).
- **Design:** **`bas_build_spec/frontend_example/graphic.html`** dark BAS tokens—dense but legible field UI.
- **Next Codex wake clock (for dashboard):** `cd …/cron_codex && ./bin/bas_wake_status.sh` (or `./bin/bas_workspace_cli.sh wake-status`) prints JSON: **`next_fire_utc`**, **`seconds_until_next`** (countdown source), **`last_wake_log`** (`size_bytes`, **`duration_seconds`**, **`tokens_used_sum`**). Matches **`cron/jobs.json`** schedule (UTC in engine—label UI). `bas_app` can poll this or a thin API wrapper later.
